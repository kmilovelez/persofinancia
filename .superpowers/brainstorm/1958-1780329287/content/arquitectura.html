¿Qué arquitectura usamos?

3 enfoques para construir PersoFinancIA — con sus trade-offs

A

Next.js 14 + Supabase + Vercel AI SDK Recomendado

Stack moderno y cohesivo. Next.js maneja UI y API en un solo repo. Supabase para auth + DB con RLS por usuario. Vercel AI SDK para el chat con Claude. PWA para experiencia móvil nativa.

Stack
Next.js 14 (App Router)
Supabase Auth + DB + Storage
Vercel AI SDK + Claude API
shadcn/ui + Tailwind
Recharts (gráficas)
Vercel (deploy gratuito)
Ventajas
Un solo repo
Deploy en minutos
PWA = app en tu celular
API keys en servidor
Ecosistema enorme

Contras

  • Claude API tiene costo por uso
  • Vercel limita Edge Functions gratis
B

Next.js + Supabase + IA como Edge Function separada

La IA corre como Supabase Edge Function (Deno). Más flexible para lógica compleja de análisis financiero. Más piezas, pero mejor separación de responsabilidades.

Stack
Next.js 14 (frontend)
Supabase Edge Functions (IA)
Supabase Auth + DB
Claude API (desde Edge Fn)
shadcn/ui + Tailwind
Ventajas
IA aislada del frontend
Lógica financiera compleja
Sin cold starts en Vercel
Edge Fn corren cerca del usuario

Contras

  • Más piezas que mantener
  • Debug más complejo
C

T3 Stack (Next.js + tRPC + Prisma + NextAuth)

Stack tipado de extremo a extremo. tRPC elimina la necesidad de REST API manual. Prisma como ORM en vez de Supabase SDK directo. Popular en proyectos TypeScript serios.

Stack
Next.js + tRPC + Prisma
NextAuth (auth)
PostgreSQL (Supabase DB)
Claude API
shadcn/ui + Tailwind
Ventajas
Type-safety total
Autocompletado perfecto
Patrón bien establecido

Contras

  • Más boilerplate inicial
  • Pierdes features de Supabase (realtime, storage)
  • Más complejo para un solo dev
